# Field Map PRD: Fable review (2026-11-14)

Reviewer: `plan-reviewer` agent (Fable), read-only, on the first draft of `docs/specs/2026-11-14-field-map-prd.md`. Checked against the JSONata docs and source, the data-tools core library, Join Receipt's PRD, plan and tests, the earlier Join Receipt review, Answerability Check's DDL parser and ADR 0004, and the git history. Verdict: **build it after the blockers**. Both blockers were PRD-level fixes, made before any fixture labels exist.

| # | Severity | Finding | What changed in the PRD |
|---|---|---|---|
| 1 | Blocker | "pandas and SQL equal JSONata byte for byte" can't hold. JSONata returns a one-item array as a bare value, drops keys whose value is missing (keeps `null`), rounds `$string` to 15 significant digits, loses integers above 2^53, and `$number("abc")` throws and aborts the record. `coalesce`, `concat` and `pick` differ on missing vs null. Trim, lowercasing and date formats differ by runtime. Join Receipt's own pandas test only checks row counts | F11 split into determinism (byte-identical transform text) and equivalence (equal in a written canonical form). Per-op semantics in the grammar table. Guarded casts. Big integers read as strings. "Maps one to one" removed |
| 2 | Blocker | The grammar couldn't fill a target array of objects, which is the orders-with-line-items example itself | `nested` op added (one level deep in v1), with a context path in `fieldmap.yml`; deeper nesting is a non-goal; a sample with line items is required |
| 3 | Serious | "Silent error rate ≤ 5%" is gameable by asking about everything, and the thresholds were tunable on the same fixtures | Metrics are now confident precision plus coverage, per labelled field; T = 60 and G = 10 frozen in the PRD; held-out set scored with frozen values only |
| 4 | Serious | Value fit has nothing to score against with a column list, little with an example record, and can't separate three `number` prices | Score adds source-side evidence; accuracy reported per target kind; inferred schemas get a confirm-and-loosen step; the FAQ says what a column list gets |
| 5 | Serious | Masking fails both ways: shape-masked values make questions unanswerable, there's no "looks personal" classifier in core, and a masked model payload removes the signal | Raw values on screen with a hide toggle; model payload passes categorical values through (≤ 50 distinct, not email) |
| 6 | Serious | Reuse overstated: no URL/UUID format class, no JSON profiler, the DDL parser is in another repo pending ADR 0004, and the whole core exists only on an unmerged Join Receipt PR stack | F3 lists only existing classes; F17 depends on ADR 0004; "Join Receipt PRs merged first" is a blocking open question |
| 7 | Serious | Sized in weeks with no referent; scope is about 1.5–2× Join Receipt | Phasing as plan tasks against Join Receipt's actual history; OpenAPI and the SQL emitter moved to P1; fixture downloads attended and committed |
| 8 | Worth knowing | Cents can't be told from values; epochs false-positive on 10-digit IDs and miss µs/ns | `scale` only from a name or `multipleOf`, otherwise a question; epochs only for date targets or time-like names, 1990–2040 sanity flag, µs/ns added |
| 9 | Worth knowing | JSONata replacing DuckDB as the deciding engine is a family convention change presented as settled | Named in §8; family doc reworded in the same PR |
| 10 | Worth knowing | superglue is FSL, not open source; JSONata 2.x point releases changed expression output; the Python port is third-party | Corrected; exact `jsonata` version pinned in `fieldmap.yml` |
| 11 | Worth knowing | Shares from 3 samples read as more certain than they are | Counts below 10 records; `coalesce` from "sometimes present" needs ≥ 10 |
| 12 | Worth knowing | ajv needs `Ajv2020` and `ajv-formats`; a remote `$ref` must error, not fetch; evaluation belongs in a worker | All three in F1, F2, F7 |

Not checked by the reviewer: drift-check semantics beyond a read, the MaDI-Bench data licence, the five sample APIs' licences, accessibility, exact `$toMillis` defaults, pandas `json_normalize` and DuckDB `read_json` behaviour (reasoned, not run).
